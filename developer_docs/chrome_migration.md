## 結論
現在のクラウドRoutine `東京アフタヌーンティー毎週更新` / `afternoon-tea-weekly` からClaude in Chromeを利用できる接続は確認できていない。移行は未実施。指示だけでChrome利用を有効化しない。

## 確認した根拠
- Claudeの既存タスク編集画面で対象リポジトリ、環境、毎週月曜07:17 JST、有効、次回11月16日07:17を確認した。
- コネクタは未設定。追加候補にはAnthropic Economic Index、Gmail、Google Drive、Notionがあり、Chromeは表示されなかった。これは当該画面の観測であり、製品全体の非対応を断定するものではない。
- 現在の端末でClaude Code CLIはPATH上に見当たらなかった。拡張機能の導入・認証・接続は検証していない。
- [Chrome公式説明](https://code.claude.com/docs/en/chrome)はCLI/VS Code連携、Chrome拡張、直接のAnthropicプランとログイン、`claude --chrome` と `/chrome` による接続確認を案内している。ブラウザーのログイン状態を共有するため、匿名調査は別途確認が必要。
- [クラウド定期実行](https://code.claude.com/docs/en/routines)はリポジトリ・環境・コネクタで到達範囲が決まる。既存Routineから利用者のChromeを無人操作する手順は今回確認できなかった。
- [スケジュール比較](https://code.claude.com/docs/en/scheduled-tasks)によればDesktop定期実行はPC稼働が必要。ローカル定期実行とChrome連携を組み合わせられるかは実機検証が必要であり、動作保証ではない。
- [Desktopの説明](https://code.claude.com/docs/en/desktop)では内蔵BrowserとChrome拡張は別機能。内蔵Browserでの成功をChrome拡張での成功とは扱わない。

## 移行案（未有効化）
1. 正式に対応する実行経路を選び、まず対話型Claude CodeでChrome接続を確認する。クラウドを維持する場合は当該環境からの接続手順と実ブラウザーツールの存在が必要。
2. Chrome連携で調査先サイトのログイン済み状態を利用しないことを確認する。対応する専用プロファイル等で匿名閲覧を保証できなければ中止。既存ログインを無断で解除しない。
3. ローカルへ移す場合はPC・Chrome・実行するClaudeアプリ/プロセスの稼働、認証、許可待ち、スリープと再起動時の挙動を検証する。クラウドRoutineの環境欄を書き換えるだけでローカル化できるとは扱わない。
4. 移行先を無効状態で準備し、ローカルのモックで読み取り、証拠保存、予約拒否、制限検知、中断と再開を検証する。
5. 匿名かつ許可された少数の公式ページを実際の実行環境から読み、ツール名・URL・確認日時・短い根拠・実行結果を保存する。認証情報や個人情報は保存しない。
6. 検証に合格してから切替時刻を決め、旧起動を停止し、新起動だけを月曜07:17 Asia/Tokyoにする。旧起動の停止と新起動の有効化を照合し、二重起動を残さない。
7. 同一週の実行・既存PR・公開記録から再開し、別名PRを増やさない。接続失敗・承認待ち・調査中断は未完了として保存し公開しない。
